# Формат рецепта — предложение v1

Статус: проект для обсуждения, не согласованное решение VISION.

Схема: `schemas/recipe.schema.json`. Пример: `schemas/recipe.example.json`.

## Границы данных

RecipeContent хранит содержимое рецепта. ID записи в БД, автор, даты, версия записи для защиты от одновременного редактирования, источник (вручную / LLM) и исходный чат — метаданные хранения вне содержимого. Связь локального ingredient.id с нормализованным продуктом для поиска хранится отдельно; модель не придумывает ID справочника.

Порядок массивов задаёт порядок ингредиентов и шагов. Локальные ID сохраняются при правках существующих элементов. Номер шага вычисляется при отображении. Режим шагов, выбранное число порций, отмеченные ингредиенты, текущий шаг и состояние таймеров — состояние интерфейса, не рецепт.

## Время и количества

totalMinutes — время от начала приготовления до готовности, включая ожидание, маринование и охлаждение, если они обязательны. activeMinutes — занятость повара. Активное время не превышает общее. Общее время не выводится суммированием шагов: действия могут идти параллельно. В карточке: «35 мин (20 мин)».

В quantities различаются точное количество, диапазон, «по вкусу» и «по необходимости». Единицы заданы кодами; русские подписи — задача интерфейса. Чашки пока не включены из-за различий объёма. Ложки не переводятся в граммы без данных о продукте.

Исходные quantities относятся к servings. При выборе другого числа порций оба края диапазона или точное количество умножаются на отношение порций. Исходник не меняется; округляется только отображение. Штучные продукты могут стать дробными: приложение не округляет их молча до целого. Время и таймеры не масштабируются. «По вкусу» и «по необходимости» остаются текстом.

## Шаги

Один массив steps обслуживает и ленту, и режим по одному шагу. title — короткое действие; instruction — полноценное описание с температурой, огнём и признаком готовности при необходимости. ingredientIds показывает, какие продукты понадобятся, но не распределяет их количество между шагами. Повторная ссылка на ингредиент не означает повторный расход всей порции. При частичном использовании инструкция явно говорит «половина», «оставшаяся часть». В списке ингредиентов показано общее количество на рецепт. В текущем чистом макете список продуктов внутри каждого шага скрыт; ссылки остаются в данных.

timerSeconds — опциональный таймер шага. Запуск и уведомления требуют отдельной реализации; в макете таймеры только подписи. Для v1 допускается один таймер на шаг. Заметки пользователя выводятся после шагов.

## Проверка и LLM

JSON Schema проверяет форму, типы и локальные ограничения. Дополнительно код проверяет activeMinutes <= totalMinutes, min <= max у диапазонов, уникальность ID ингредиентов и шагов, существование всех ingredientIds, непустой после удаления пробелов текст. Неиспользованные в шагах продукты стоит подсвечивать как предупреждение, а не автоматически удалять.

Это каноническая схема приложения, а не обещание совместимости всех её ключевых слов со всеми LLM. В Python описываем соответствующие модели Pydantic и проверяем поддержку экспортированной схемы конкретным провайдером. Модель генерирует отдельный RecipeDraft без userNotes и метаданных. После полной проверки сервер добавляет schemaVersion и сохраняет существующие пользовательские заметки. При неполном ответе или ошибке черновик не заменяет сохранённый рецепт.

Ручная незавершённая форма может храниться как черновик отдельно; каноническая схема описывает полноценный рецепт. Переключение режима чтения и пересчёт порций не требуют обращения к модели.
