# RecipeBook

Рабочая первая версия личной книги рецептов: Python/FastAPI, SQLite, React/TypeScript и адаптер LangChain для OpenAI.

## Запуск локально

Зависимости уже установлены в `pyenv RecipeBook` и `frontend/node_modules`.

```sh
sh scripts/dev.sh
```

Открыть http://127.0.0.1:5173 и нажать «Локальный вход». Скрипт запускает API на 8000 и фронтенд на 5173. Рецепты сохраняются в `data/recipebook.db`. Папка данных исключена из Git.

Этот режим намеренно использует **тестовую модель**: она возвращает демонстрационный рецепт, а не генерирует ответ на запрос. В интерфейсе есть соответствующая подпись. Локальный вход доступен только с loopback и только в development.

Для установки на другом компьютере с существующим окружением `RecipeBook`:

```sh
PYENV_VERSION=RecipeBook pyenv exec pip install -r backend/requirements.lock
npm --prefix frontend ci
```

Нужны Python 3.11 и Node 24. Python-зависимости зафиксированы в `requirements.lock`, фронтенд — в `package-lock.json`.

## Что работает

- Библиотека: поиск по названию, фильтр общего времени и всех выбранных продуктов.
- Ручное создание и редактирование: ингредиенты, точные количества/диапазоны/«по вкусу», группы, шаги, порядок, заметки.
- Просмотр: порции, отметки ингредиентов, лента или один шаг, согласованный светлый дизайн с прямыми углами.
- Чаты и история, идеи, структурированный черновик, сохранение нового рецепта или применение к исходному.
- Защита заметок, проверка версий при изменении и повторных запросов при генерации/сохранении.
- Проверка подписи Telegram initData и доступа одного пользователя, серверные HttpOnly-сессии.

## Настоящая модель и Telegram

Все значения задаются в корневом `.env`, образец — `.env.example`. Не отправляйте ключи в чат и не добавляйте их в Git. Фронтенд не получает ключ модели или токен бота.

Для настоящей модели заполните `LLM_API_KEY`, `LLM_MODEL`, оставьте `LLM_PROVIDER=openai`. Выберите модель с поддержкой структурированного вывода. Реальные API-запросы в ходе разработки не выполнялись. Для запуска с настройками `.env` (без принудительной тестовой модели):

```sh
PYENV_VERSION=RecipeBook PYTHONPATH=backend/src pyenv exec uvicorn recipebook.main:app --host 127.0.0.1 --port 8000
npm --prefix frontend run dev
```

Для браузерной локальной разработки можно явно поставить `DEV_AUTH_ENABLED=true` в `.env`. Для Telegram нужны `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_USER_ID` и `PUBLIC_APP_URL` с адресом Mini App. В production поставьте `APP_ENV=production`, `DEV_AUTH_ENABLED=false` и используйте HTTPS. Без корректной конфигурации production не запускается.

Сборка интерфейса: `npm --prefix frontend run build`. Для размещения reverse proxy должен отдавать `frontend/dist` с SPA fallback и направлять `/api` в FastAPI. Запускайте один процесс API: фоновой очереди задач пока нет. При перезапуске незавершённая генерация помечается прерванной.

## Проверки

```sh
PYENV_VERSION=RecipeBook PYTHONPATH=backend/src pyenv exec pytest -q backend/tests
npm --prefix frontend test
npm --prefix frontend run build
```

## Границы первой версии

Таймеры пока отображают длительность; фоновых уведомлений нет. Несохранённая форма живёт в памяти страницы. Для небольшого личного приложения SQLite хранит типизированное содержимое в JSON-записях, поиск выполняется по загруженным рецептам. Таблица создаётся при первом запуске; миграции понадобятся при первом изменении схемы хранения. История чатов пока загружается целиком. Автоматического повтора платного запроса нет. Проверка рецепта обеспечивает структуру, но не проверяет кулинарную достоверность.

Документы в `docs/` описывают первоначальный расширенный проект; фактическая реализация намеренно проще. Основные входные точки: `backend/src/recipebook/main.py`, `backend/src/recipebook/domain/recipe.py`, `backend/src/recipebook/llm/assistant.py`, `frontend/src/main.tsx`.
